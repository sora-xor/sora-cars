## Native preparation

`street_v1::accepted::prepare` bounds and checks the selected snapshot before
cloning admission or compiling. It requires exact canonical Norito
`StreetParametersV1` bytes and the closed track's manifest dimensions. It
validates the final claim's shape and terminal tick, compiles the complete
`GameAdmissionBodyV1`, then validates accepted history against the actual
instance relation and genesis commitment. Skin data, wallet/input keys, NFT
wagers and resource terms remain part of admission. The stock compiler rejects
returnable equipment rather than silently ignoring its effect.

Every removal cell comes from `ValidatedHistory::removals_at`; every driving
cell comes from `accepted_payload`. The literal six-control batch is validated
in full, including any suffix after a selected terminal tick. An absent payload
means the validated inactive-slot encoding. Callers cannot supply alternative
tapes, mappings, callbacks or weakened limits through this adapter.

`CompiledStreetInstanceV1::into_sequence` consumes the real programs. Borrowed
AIR and owned-program entry points share one guarded constructor, including
default core policy, resource admission and zero-motion handling. It preserves
the complete unused motion source at zero motion without preparing its unused
membership relation. These allocation estimates do not bound whole-process RSS
or erase the caller's earlier compilation allocations.

The prepared value borrows immutable session/evidence and owns its sequence.
`segments()` selects the native width-two policy, splitting at the selected
checkpoint. Its sealed binding fixes both sequence digests and the segment
count; a worker cannot replace this with another partition. The segment verifier
checks the actual relation, genesis, context, tape cells and internal
boundary/motion order. The native state callback checks the raw state at the
selected checkpoint before applying its removal boundary. After the complete
sequence verifies, `finish` projects its full terminal output and compares any
archived outcome. Preparation also checks the unverified claim's shape; that
preflight grants no proof authority. Verifier execution does not evaluate the
driving graph. The applied public-bundle path owns authenticated finalized
source/evidence while preparation borrows them; complete aggregate verifier
resource admission is still a separate integration.

## Identity and authority

The unregistered implementation ID frames the compiler-family identity, fixed
protocol description, geometry parameters and 34 selected native source files.
The compiler family has its own 21 source includes. The ID is fixed across
rosters and sessions; concrete emitted relations and execution statements bind
their instance data separately. Included comments and inline tests also affect
the source pin. Native Poseidon2 and its constants, the actual shared field and
transcript code, model/custody support and signature/hash implementation files
are included explicitly.

This inventory does not cover the entire transitive dependency, derive, build,
compiler or platform closure. Its value occupies the existing policy profile
field in local test records, but no `ExecutionProofProfileV1` is registered.
Neither an implementation ID nor an expected snapshot hash authenticates
finalized ledger inclusion, legal removals, or expiration of a consensus
deadline. The accepted-verifier receipt continues to report those limits.

## Remaining work

This adapter supplies the complete native computation and accepted-input
association for matched backend experiments. It still needs bounded compact
full-race proof transport with a complete final decider, independently
authenticated producer/finality context, composed security qualification,
supported hardware parity and real four-validator settlement evidence. No
wallet flow, live XOR/NFT settlement or Taira/SoraFS activation follows from
this integration. The current six-tick public proof fits within 4,194,304 bytes,
but covers only 0.2 simulated seconds; that result does not establish a bounded
full-race envelope. The earlier unsegmented six-tick proof exceeded that limit.

[September research briefing](research/september-2026-briefing.md)
for accumulation, lookup and commitment candidates and their evidence limits.
