**The exact missing public binding**

The new envelope must bind canonical network/session identity, exact compiled source and geometry/catalog/rules/profile identities, original slot-ordered wallets and input keys, immutable participant equipment/classes and wager policy, genesis, terminal claim and retained session revision/epoch. Include the selected checkpoint's tick/state/transcript/terminal/signatures, immutable anchors, complete forced batches/removals, pending certificate, current commitments and matching reveals, and `next_tick`. Derive the executed action tape and checkpoint state from that data; hashing opaque caller-selected bytes does not validate it.

The generic [session schema](../../iroha/crates/iroha_data_model/src/game.rs:284) already retains those frontier fields. [Checkpoint admission](../../iroha/crates/iroha_core/src/smartcontracts/isi/game.rs:687) forbids discarding a pending certificate at the same frontier; [deadline advancement](../../iroha/crates/iroha_core/src/smartcontracts/isi/game.rs:915) carries its commitments into forced reveals. A history adapter must preserve this protection: missing reveals before cutoff cannot become neutral controls or an earlier favorable checkpoint. Verify original-roster signatures, exact session/epoch/slot domains, reveal commitments, ordered batch coverage and a bijection between removal markers and forced removals. Block-height decisions come from consensus, not proof-worker clocks.

There is a version gap: the documented shared `game_history` implementation belongs to a private candidate. The inspected maintained tree instead has [classed history:133](../../iroha/crates/iroha_core/src/execution_proofs/classed_race_v1/history.rs:133), which rejects removals after terminal, and a [dispute hash:27](../../iroha/crates/iroha_core/src/execution_proofs/classed_race_v1/history.rs:27) that projects epoch/checkpoint/anchors/forced batches, omitting the current pending frontier. Locate and freeze that candidate or implement a new canonical complete snapshot validator; do not assume the maintained hash authenticates the documented policy.

**Terminal semantics need an explicit closure relation**

The policy requires removals at T to affect awards without another driving tick; later removals remain retained history only. Street currently gates forfeits with `!previous_done`, so feeding removals into an extra terminal tick ignores them. `CompleteExecution` also rejects that extra tick. A separate compiler-owned no-driving finalizer must apply exactly the T removal set, preserve physical state/cursor, clear disqualified finish records and recompute eligible ranking, technical win/refund and winner slots. Later removals must not re-filter those winners.

The document specifies earliest terminal **batch boundary**, whereas the raw terminal policy enforces earliest terminal **transition**. Freeze one precise adapter rule for mid-batch completion, checkpoint-before-removal state, terminal-only closure and the possible T=0 case before claiming policy equivalence. Existing terminal padding cannot stand in for later accepted controls: retain and canonically validate the entire tail, but execute only the specified prefix.

**Recommended next artifact: `native_history_component` laboratory**

Build a new immutable `CompiledHistory` with explicit state/action maps and a bounded `HistoryStatement`. Initially verify an ordered vector of the existing per-transition proofs. Each proof authenticates all public outputs; the envelope checks every carried input against the preceding authenticated output, initial state against genesis, actions against the validated tape, and the four terminal predicates. Include transition index, total count and common statement digest in each binding. Check exact canonical wire length, root/proof order and EOF; stream verification and retain only the preceding output vector. This is a complete component-proof composition, not succinct aggregation.

Compile the terminal finalizer as its own complete checked relation and bind its authenticated result to the envelope. Keep independent oracle tails enforced by each component; any envelope padding must have a separate fixed zero rule. Never drop repeated operands, ranges, ROMs or constant contradictions while joining steps.

Exercise two/eight cars over the retained three-tick technical-win fixture, all-forfeit closure and a finish-fraction fixture. Reject swapped/duplicate/omitted proofs, stale history, changed roster/track, modified carry/object mask, pending-input omission, forged removals, early cutoff, extended driving, nonzero tails and terminal-boundary winner changes. Remove witness paths for verifier processes and compare all native nodes during fixture generation only. Report separate flags for ordered component verification, history authentication, integer/security qualification and finalized inclusion. A public standalone snapshot remains unauthenticated until consensus or a finalized-ledger verifier supplies its authority.
